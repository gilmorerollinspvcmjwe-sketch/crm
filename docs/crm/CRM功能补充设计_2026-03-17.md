## 二、B端核心功能设计

### 2.1 审批流程设计方案

#### 2.1.1 审批流程类型

| 流程类型 | 触发场景 | 审批人规则 | 审批条件 |
|---------|---------|-----------|---------|
| 合同审批 | 合同金额≥X万元 | 部门经理→财务→总经理 | 金额梯度 |
| 报价审批 | 报价单折扣≥X% | 销售主管→销售经理 | 折扣梯度 |
| 回款审批 | 回款金额≥X万元 | 财务主管→总经理 | 金额梯度 |
| 特殊折扣审批 | 折扣申请 | 销售经理→总经理 | 折扣比例 |
| 退款审批 | 退款金额≥X元 | 财务→法务→总经理 | 金额梯度 |
| 线索转移审批 | 线索负责人变更 | 原负责人→新负责人 | 需要双方确认 |

#### 2.1.2 审批流程配置数据模型

```typescript
/** 审批流程定义 */
interface ApprovalFlow {
  id: string;
  name: string;
  type: ApprovalType;
  module: string;
  triggerCondition: TriggerCondition;
  nodes: ApprovalNode[];
  ccUsers: string[];
  timeout: number;
  timeoutAction: 'pass' | 'reject' | 'notify';
  enabled: boolean;
  createdBy: string;
  createdAt: string;
}

/** 审批节点 */
interface ApprovalNode {
  id: string;
  name: string;
  type: 'approver' | 'condition' | 'cc';
  approverType: 'user' | 'role' | 'department_head' | 'manager' | 'custom';
  approverIds: string[];
  condition?: Condition;
  actions: ApprovalAction[];
  timeout: number;
}

/** 触发条件 */
interface TriggerCondition {
  field: string;
  operator: 'eq' | 'gt' | 'lt' | 'gte' | 'lte' | 'in';
  value: any;
}

/** 审批记录 */
interface ApprovalRecord {
  id: string;
  flowId: string;
  recordId: string;
  recordType: string;
  currentNodeId: string;
  status: 'pending' | 'approved' | 'rejected' | 'cancelled';
  approvers: ApprovalHistory[];
  createdAt: string;
  completedAt?: string;
}

/** 审批历史 */
interface ApprovalHistory {
  nodeId: string;
  approverId: string;
  approverName: string;
  action: 'approve' | 'reject' | 'transfer' | 'delegate';
  comment?: string;
  timestamp: string;
}
```

#### 2.3.2 数据模型设计

```typescript
/** 自动化规则 */
interface AutomationRule {
  id: string;
  name: string;
  module: string;
  triggerEvent: TriggerEvent;
  conditions: Condition[];
  actions: AutomationAction[];
  isActive: boolean;
  executionCount: number;
  lastExecution?: string;
  createdBy: string;
  createdAt: string;
  updatedAt: string;
}

/** 触发事件 */
type TriggerEvent = 
  | 'record.created'
  | 'record.updated'
  | 'record.deleted'
  | 'field.changed'
  | 'schedule.cron'
  | 'days.inactive'
  | 'days.before'
  | 'days.after';

/** 自动化动作 */
interface AutomationAction {
  type: ActionType;
  config: Record<string, any>;
}

/** 动作类型 */
type ActionType = 
  | 'assign.owner'
  | 'assign.pool'
  | 'update.field'
  | 'create.record'
  | 'create.task'
  | 'send.notification'
  | 'call.webhook'
  | 'execute.script';

/** 执行日志 */
interface AutomationLog {
  id: string;
  ruleId: string;
  ruleName: string;
  triggerData: Record<string, any>;
  actions: {
    type: ActionType;
    status: 'success' | 'failed';
    result?: string;
    error?: string;
  }[];
  executedAt: string;
  duration: number;
}
```

## 五、实施建议

### 5.1 开发优先级建议

**第一阶段（P0核心功能）**:
1. 组织架构 - 部门管理、人员管理
2. 数据权限 - 角色数据范围配置
3. 审批流程 - 流程配置、审批处理
4. 流程自动化 - 线索自动分配

**第二阶段（P1重要功能）**:
1. 审批流程 - 审批通知、审批日志
2. 客户管理 - 导入导出、客户标签
3. 合同管理 - 合同模板
4. 报表统计 - 自定义报表

**第三阶段（P2增强功能）**:
1. 合同电子签
2. 系统日志
3. API接口管理
4. 数据同步

### 5.2 技术注意事项

1. **审批流程**: 考虑使用工作流引擎（如Activiti、Flowable）或自研简易流程
2. **数据权限**: 在查询层统一注入数据权限过滤条件
3. **自动化**: 使用消息队列处理异步任务，避免阻塞主流程
4. **电子签**: 建议集成第三方电子签章服务（如e签宝、法大大）
