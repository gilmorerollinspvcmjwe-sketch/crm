## 一、工作流概述

### 1.1 什么是工作流

工作流（Workflow）是 CRM 系统的**低代码规则引擎**，核心价值在于：**将重复性销售/客服/营销操作自动化，释放人力，让系统代替人执行规则**。

没有工作流的 CRM 约等于高级 Excel 通讯录，徒有数据而无管理能力。

工作流将业务规则从代码层抽离为可视化配置，业务人员无需编写代码，即可定义：
- 什么情况下触发（Trigger）
- 满足什么条件走什么分支（Condition）
- 执行什么操作（Action）

### 1.2 核心逻辑：触发器 -> 条件 -> 动作

```
触发器 (Trigger) --> 条件 (Condition) --> 动作 (Action)

事件驱动入口         分支判断              执行结果
- 记录创建          - AND/OR 组合        - 发送邮件
- 字段变更          - 属性比较            - 分配负责人
- 定时调度          - 嵌套条件            - 更新属性
- Webhook           - 多分支 Switch       - 调用 API
```

**完整工作流示例（新线索自动分配）**：

```
[触发器] 当「线索」被创建时
    |
[条件] 如果「线索来源」等于「官网表单」
    |
  [是] --> [动作] 分配给「官网组」负责人
    |
  [否] --> [动作] 分配给「渠道组」负责人
    |
[动作] 发送分配通知邮件给负责人
```

### 1.3 工作流 vs 手动操作的价值对比

| 维度 | 手动操作 | 工作流自动化 |
|------|---------|------------|
| **执行速度** | 分钟~小时级（依赖人工） | 秒级（系统自动执行） |
| **一致性** | 因人而异，执行标准不一 | 100% 统一，按规则执行 |
| **规模化** | 人工处理有上限 | 无上限，支持批量 |
| **实时性** | 无法 7x24 小时监控 | 24/7 实时监控触发 |
| **错误率** | 高（人为主观判断） | 低（规则明确则无误） |
| **可追溯** | 靠笔记/记忆，不可靠 | 完整执行日志，每步可查 |
| **成本** | 持续人力成本 | 一次性配置，长期复用 |

## 二、工作流触发器（Triggers）

### 2.1 触发器概述

触发器是工作流的入口节点，决定了「何时」开始执行工作流。每个工作流**必须有且仅有一个**触发器。

HubSpot 文档定义了 5 类触发器：
1. **Filter-based（过滤条件触发）**：当记录满足某条件时触发
2. **Event-based（事件触发）**：当某事件发生时触发
3. **Based on a schedule（定时触发）**：按 Cron 表达式定时触发
4. **Webhook 触发**：接收到外部 Webhook 时触发
5. **Manual（手动触发）**：由用户手动发起

### 2.2 对象触发器（Object Triggers）

基于 CRM 对象（客户/联系人/商机/合同/工单/线索）的生命周期事件触发。

#### 2.2.1 创建记录时

| 配置项 | 说明 |
|--------|------|
| 触发类型 | 对象创建 |
| 适用对象 | 全部（客户/联系人/商机/合同/工单/线索） |
| 是否包含子对象 | 父子对象同时创建时是否都触发 |
| 筛选条件 | 可选，仅满足条件的记录才触发 |

**示例场景**：
- 新线索创建时，自动发送欢迎邮件
- 新客户创建时，自动分配负责人

#### 2.2.2 更新记录时

| 配置项 | 说明 |
|--------|------|
| 触发类型 | 对象更新 |
| 触发频率 | 每次更新 / 仅首次满足条件时 |
| 监听属性 | 可指定具体属性（仅当该属性变更时触发） |

**示例场景**：
- 商机阶段变更时，通知负责人
- 客户等级变更时，更新标签

#### 2.2.3 特定字段变更时（Property Changes）

| 配置项 | 说明 |
|--------|------|
| 触发类型 | 属性变更 |
| 属性选择 | 单选 |
| 变更方向 | 变为 / 从...变为（可选旧值） |

**示例**：
- 「商机阶段」从「方案报价」变为「谈判」
- 「客户等级」变为「A」
- 「最后联系日期」不为空

**示例场景**：
- 商机阶段从「需求确认」推进到「方案报价」，自动创建报价任务
- 客户状态变为「成交」，触发合同创建流程

#### 2.2.4 进入/离开阶段时（Stage Changes）

| 配置项 | 说明 |
|--------|------|
| 触发类型 | 阶段变更 |
| 适用对象 | 商机/工单（支持阶段的实体） |
| 触发时机 | 进入 / 离开（可多选） |
| 特定阶段 | 可选，限定特定阶段 |

**示例场景**：
- 商机进入「赢单」阶段，自动发送成交恭喜邮件
- 工单离开「处理中」进入「待验证」，通知客户验证

#### 2.2.5 删除记录时

**示例场景**：
- 删除客户时，自动创建备份工单（记录删除数据）
- 删除商机时，检查是否有关联合同

### 2.3 时间触发器（Time-Based Triggers）

基于时间或日期条件触发。

#### 2.3.1 定时执行（Scheduled / Cron）

| 配置项 | 说明 |
|--------|------|
| 触发类型 | 定时调度 |
| 配置方式 | Cron 表达式或可视化配置（每日/每周/每月） |
| 时区 | 选择时区 |
| 执行时间 | 精确到分钟 |

**注意**：定时触发器通常需要配合「筛选条件」才能精确锁定记录，否则会作用于所有记录。

#### 2.3.2 延迟后执行（After X Days/Hours）

| 配置项 | 说明 |
|--------|------|
| 触发类型 | 相对延时 |
| 时间单位 | 天/小时/分钟 |
| 基准时间 | 记录创建时间 / 属性变更时间 / 日期属性值 / 上次活动日期 |

**示例场景**：
- 线索创建 3 天后未跟进，发送催促邮件
- 合同到期前 30 天，发送续约提醒
- 客户生日当天 9:00 发送祝福邮件

#### 2.3.3 到达特定日期时（On a Specific Date）

| 配置项 | 说明 |
|--------|------|
| 日期属性来源 | 合同到期日 / 生日 / 计划跟进日期 / 自定义日期字段 |
| 相对偏移 | 到期前 X 天 / 到期当天 / 到期后 X 天 |
| 时间点 | 当天 00:00 / 具体时间（如 09:00） |

#### 2.3.4 活动超时（No Activity for X Days）

| 配置项 | 说明 |
|--------|------|
| 超时阈值 | 天数 |
| 活动类型 | 邮件交互 / 电话通话 / 会议 / 跟进记录 / 任意活动 |
| 基准 | 最后任意活动日期 / 最后特定类型活动日期 |

**示例场景**：
- 客户 30 天无任何活动，通知负责人主动跟进
- 商机 45 天无阶段推进，预警主管

### 2.4 事件触发器（Event-Based Triggers）

#### 2.4.1 邮件事件

| 子类型 | 说明 |
|--------|------|
| 邮件已发送 | 工作流内发送的邮件被发出 |
| 邮件已打开 | 追踪像素检测 |
| 邮件已点击 | 链接点击追踪 |
| 邮件发送失败 | 发送失败 |
| 邮件回复 | 客户回复邮件 |

| 配置项 | 说明 |
|--------|------|
| 邮件模板 | 可选，监听特定模板 |
| 打开/点击次数 | >=1次 / >3次 |
| 时间窗口 | 事件发生后 X 小时内触发 |

**示例场景**：
- 发送产品介绍邮件后 3 天客户未打开，再次发送提醒邮件
- 客户点击了报价链接，通知销售及时跟进

#### 2.4.2 表单提交

| 配置项 | 说明 |
|--------|------|
| 表单选择 | 单选或多选 |
| 特定字段值条件 | 可选 |

**示例场景**：
- 官网表单提交，创建线索并分配给市场负责人
- 填写「演示申请」表单，立即创建商机并通知销售

#### 2.4.3 页面访问

| 配置项 | 说明 |
|--------|------|
| 页面 URL | 支持通配符 / 正则 |
| 访问次数阈值 | 次数 |
| 时间窗口 | 天数 |
| 访客类型 | 新访客 / 回访客 |

**示例场景**：
- 客户访问「价格页」超过 3 次，标记为高意向，分配给销售
- 访问「联系我们」页面，创建跟进任务

#### 2.4.4 API 调用

内部 API 触发：支付系统回调创建回款记录，ERP 系统推送订单数据创建客户/商机。

#### 2.4.5 Webhook 接收

| 配置项 | 说明 |
|--------|------|
| Webhook URL | 系统生成 |
| 签名密钥 | HMAC 验签 |
| 事件类型 | 来自外部系统的事件名 |
| 数据映射 | 外部数据 -> CRM 字段映射规则 |

**示例场景**：
- 电商平台订单完成，触发客户创建流程
- 呼叫中心通话结束，触发满意度评分流程

### 2.5 手动触发（Manual Enrollment）

| 配置项 | 说明 |
|--------|------|
| 批量触发 | 是否允许 |
| 触发入口 | 记录列表 / 详情页 / 批量操作 |

**示例场景**：
- 销售手动选择一批客户，发送定向营销邮件
- 客服手动触发工单升级流程

## 三、条件与分支（Conditions & Branching）

### 3.1 简单条件（Simple Filters）

#### 3.1.1 属性值比较

| 操作符 | 说明 | 示例 |
|--------|------|------|
| = | 等于 | 客户等级 = A |
| != | 不等于 | 客户状态 != 成交 |
| contains | 包含（文本）| 标签 contains "高价值" |
| not contains | 不包含 | 名称 not contains "测试" |
| starts with | 开头是 | 邮箱 starts with "admin" |
| ends with | 结尾是 | 邮箱 ends with "@company.com" |
| > | 大于 | 商机金额 > 100000 |
| >= | 大于等于 | 客户价值 >= 500000 |
| < | 小于 | 赢单概率 < 50% |
| <= | 小于等于 | 跟进次数 <= 3 |
| is empty | 为空 | 负责人 is empty |
| is not empty | 不为空 | 手机号 is not empty |

#### 3.1.2 时间范围条件

| 操作符 | 说明 | 示例 |
|--------|------|------|
| is before | 在...之前 | 创建时间 is before 2026-01-01 |
| is after | 在...之后 | 创建时间 is after 2026-01-01 |
| is within last | 最近 X 天内 | 最后联系 is within last 30 days |
| is not within last | 不在最近 X 天内 | 跟进 is not within last 7 days |
| is between | 在...之间 | 创建时间 is between 2026-01-01 and 2026-03-01 |

### 3.2 复合条件（Compound Filters）

#### 3.2.1 AND 逻辑

所有条件必须同时满足。

```
客户等级 = A
AND 年营业额 >= 1000万
AND 负责人 is not empty
---> 同时满足才进入分支
```

#### 3.2.2 OR 逻辑

任一条件满足即可。

```
客户等级 = A
OR 商机金额 >= 100万
OR 客户状态 = 成交
---> 任一满足即可
```

#### 3.2.3 嵌套条件组

```
(条件 A AND 条件 B) OR (条件 C AND 条件 D)

示例：
(客户等级 = A AND 年营业额 >= 1000万)
OR (客户状态 = 成交 AND 最近3个月有回款)
```

### 3.3 分支节点（If/Then Branch）

#### 3.3.1 二分支（If Yes / If No）

```
  +-----------------+
  |    条件判断      |
  +--------+--------+
           |
     +-----+-----+
     |           |
    [是]        [否]
   路径A       路径B
```

#### 3.3.2 多分支（Switch Case）

```
  +-----------------+
  |  客户等级 is      |
  +--------+--------+
     |  |  |  |
    [A][B][C][D/其他]
  路径A路径B路径C 路径D
```

**示例**：
- 线索确认 --> 2小时内响应
- 初步接触 --> 24小时内响应
- 需求确认 --> 48小时内响应
- 其他阶段 --> 标准处理

#### 3.3.3 分支合并（Merge）

```
路径A ---+
         +---> [合并节点] ---> 后续动作
路径B ---+
```

## 四、工作流动作（Actions）

### 4.1 动作概述

动作是工作流对已 enroll 的记录执行的具体操作。

**执行语义**：
- 动作默认**顺序执行**
- 延迟节点（Delay）会暂停执行，计时结束后继续
- 分支节点后，各分支**并行执行**
- 「终止工作流」动作会立即停止当前记录的执行

### 4.2 数据操作（CRM Data Actions）

#### 4.2.1 更新记录属性（Update Property）

| 更新方式 | 说明 |
|---------|------|
| 设置为固定值 | 直接赋值 |
| 设置为公式值 | 拼接/数学运算 |
| 清空 | 设为空 |
| 增加/减少 | 数值属性递增/递减 |
| 追加到列表 | 多值属性（如标签）追加 |
| 从列表移除 | 多值属性移除 |

**示例**：
- 客户等级 <- "A"（固定值）
- 最近跟进时间 <- 当前时间（动态值）
- 标签 <- 追加 "高价值客户"
- 跟进次数 <- 跟进次数 + 1

#### 4.2.2 创建新记录（Create Record）

| 配置项 | 说明 |
|--------|------|
| 记录类型 | 客户/联系人/商机/合同/工单/跟进/任务 |
| 字段映射 | 触发记录属性 -> 新记录字段 |
| 关联关系 | 新建记录与触发记录的关联 |
| 级联工作流 | 创建后自动进入另一个工作流（可选） |

**示例**：
- 客户创建时，自动创建一条「首次跟进」任务
- 商机赢单时，自动创建合同草稿

#### 4.2.3 删除记录（Delete Record）

| 配置项 | 说明 |
|--------|------|
| 删除范围 | 当前记录 / 指定关联记录 |
| 确认提示 | 防止误删 |
| 级联删除 | 是否同时删除下游记录 |

#### 4.2.4 复制记录（Copy Record）

| 配置项 | 说明 |
|--------|------|
| 源/目标记录类型 | 选择复制来源和目标类型 |
| 字段映射 | 指定哪些字段复制，哪些跳过 |
| 关联复制 | 关联关系是否一并复制 |

#### 4.2.5 关联/取消关联记录（Associate / Disassociate）

| 配置项 | 说明 |
|--------|------|
| 关联类型 | 一对多 / 多对多 |
| 目标记录类型 | 选择 |
| 选择方式 | 从现有记录选择 / 动态查找 |

### 4.3 通知与通信（Communication Actions）

#### 4.3.1 发送邮件（Send Email）

| 配置项 | 说明 |
|--------|------|
| 邮件模板 | 选择或新建 |
| 收件人 | 记录关联联系人 / 指定邮箱 / 负责人邮箱 / 自定义列表 |
| 发送时间 | 立即 / 延迟 X 小时/天 / 定时 |
| 禁止重复 | 同一记录同一模板不重复发送 |

**模板变量示例**：
```
尊敬的 {{contact.name}}，
您的订单 {{deal.name}}（金额：{{deal.amount}}）已确认。
如有问题请联系您的专属顾问 {{owner.name}}。
```

#### 4.3.2 发送站内通知（Send Internal Notification）

| 配置项 | 说明 |
|--------|------|
| 通知对象 | 负责人 / 指定用户 / 用户列表 |
| 标题 | 支持变量 |
| 内容 | 支持富文本和变量 |
| 链接 | 跳转到指定页面 |
| 优先级 | 普通 / 紧急 |

#### 4.3.3 发送 IM 消息（Send IM Message）

| 配置项 | 说明 |
|--------|------|
| IM 会话 | 新建 / 指定会话 |
| 消息内容 | 支持变量，支持 Markdown |
| 附件 | 可选 |

#### 4.3.4 创建任务/待办（Create Task）

| 配置项 | 说明 |
|--------|------|
| 任务类型 | 跟进电话 / 发送邮件 / 会议 / 自定义 |
| 任务标题 | 支持变量 |
| 指派人 | 负责人 / 指定用户 / 记录所有者 |
| 到期时间 | 立即 / 触发后 X 天/小时 / 指定日期时间 |
| 优先级 | 低 / 中 / 高 / 紧急 |
| 提醒 | 到期前 X 分钟/小时/天；站内通知/邮件/SMS |

#### 4.3.5 分配负责人（Assign Owner）

| 分配方式 | 说明 |
|---------|------|
| 指定用户 | 固定分配 |
| 循环分配 | 轮询分配给多个用户 |
| 负载均衡 | 分配给当前待办最少的用户 |
| 随机分配 | 随机分配 |
| 按规则分配 | 按地区/行业/等级等规则匹配 |

**分配规则示例**：
```
IF 客户行业 = "金融" --> 分配给「金融组」
IF 客户地区 = "华南" --> 分配给「华南组」
IF 客户等级 = "A" --> 分配给「资深销售-张总」
```

#### 4.6.2 跳转到其他工作流（Go to Workflow）

将记录 enroll 到另一个工作流，同时保留当前工作流的执行上下文。

#### 4.6.3 跳转到其他动作（Go to Action）

## 九、技术架构

### 9.1 整体架构

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  前端编辑器      │     │  工作流引擎      │     │  执行调度器      │
│  (React/Flow)   │────▶│  (规则解析/校验) │────▶│  (任务队列/调度) │
└─────────────────┘     └─────────────────┘     └────────┬────────┘
                                                          │
┌─────────────────┐     ┌─────────────────┐     ┌────────▼────────┐
│  配置存储        │     │  执行日志存储    │     │  动作执行器      │
│  (PostgreSQL)   │◀────│  (Elasticsearch) │◀────│  (动作执行/回调) │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

### 9.2 核心组件

#### 9.2.1 前端编辑器
- 基于 React Flow 实现可视化拖拽编辑
- 节点校验、连接线自动生成
- 实时预览、测试运行
- 版本对比、回滚功能

#### 9.2.2 工作流引擎
- 规则解析器：将前端配置的JSON规则解析为可执行逻辑
- 校验器：校验工作流配置的合法性（死循环检测、参数缺失检测等）
- 编译器：将工作流编译为可执行的AST

#### 9.2.3 执行调度器
- 任务队列：基于 BullMQ / Redis 实现任务排队
- 定时调度：基于 Cron 实现定时触发和延迟执行
- 负载均衡：分布式环境下的任务调度均衡
- 重试机制：失败任务自动重试（指数退避）

#### 9.2.4 动作执行器
- 动作执行池：并发执行工作流动作
- 变量解析：模板变量的插值替换
- 上下文管理：工作流执行上下文传递
- 回调处理：动作执行结果回调和状态更新

### 9.3 执行语义

**保证至少一次执行（At Least Once）**：
- 任务持久化存储，执行失败自动重试
- 幂等性要求：所有动作必须支持幂等执行（重复执行不会产生副作用）

**执行隔离**：
- 租户级资源隔离
- 工作流之间互不影响
- 单个工作流执行失败不会影响其他工作流

### 9.4 性能指标
- 单工作流执行延迟：< 100ms（无延迟节点）
- 最大并发执行量：1000/秒
- 最大队列长度：100万条
- 定时触发精度：误差 < 1分钟
- 日志查询延迟：< 2s（近7天数据）
