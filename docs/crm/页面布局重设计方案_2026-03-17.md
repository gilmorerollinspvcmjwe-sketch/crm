## 二、菜单结构设计

### 2.1 设计原则
1. **按业务流程组织**：从线索到成交，按销售流程排列
2. **相关功能分组**：将关联紧密的功能放在一起
3. **层级不超过三级**：避免菜单过深
4. **命名简洁清晰**：使用用户熟悉的术语

### 2.2 菜单树结构

```
📊 工作台
└── 仪表盘 (/dashboard)
```

| **Phase 3** | 3-4天 | 详情页布局统一，Tab规范化 | P1 |
| **Phase 4** | 2-3天 | QuoteBuilder交互优化 | P2 |
| **Phase 5** | 2-3天 | 响应式适配，移动端优化 | P2 |

### 5.2 优先级排序

| 优先级 | 任务 | 工作量 | 说明 |
|--------|------|--------|------|
| P0 | 菜单结构重构 | 2h | 按业务流程重新组织菜单 |
| P0 | 路由命名统一 | 1h | 修复路由不一致问题 |
| P1 | 仪表盘布局优化 | 4h | 增加可配置性 |
| P1 | 详情页Tab规范化 | 6h | 统一各模块详情页布局 |

| P2 | 移动端适配 | 4h | 响应式布局 |

### 5.3 改动范围评估

| 模块 | 文件 | 改动类型 | 影响范围 |
|------|------|---------|---------|
| 菜单配置 | MainLayout.tsx | 重构 | 高 - 整个导航系统 |
| 路由配置 | routes/index.tsx | 优化 | 中 - URL变化 |

### 5.4 注意事项

1. **向后兼容**: 路由变更需要配置重定向，避免旧链接失效

3. **渐进式改进**: 建议分阶段实施，每次只改一个模块
4. **用户反馈**: 改版后收集用户反馈，持续优化
