## 一、升级目标概述

### 1.1 升级背景

本次升级基于五份核心分析报告：
- **《逐页代码对比分析报告》**: 识别项目 A 与项目 B 的功能差异，明确需整合的项目 B 独有功能
- **《实际功能测试报告》**: 识别当前系统的严重 Bug 和功能问题
- **《P2 功能整合报告》**: P2 级别功能（工作台组件、全局搜索、通知中心、响应式布局）已完成
- **《编译错误修复报告》**: 代码编译问题修复进展和剩余问题
- **《CRM 项目代码质量检查报告》**: 识别代码质量问题，明确 P1/P2 级别需修复的问题

### 1.2 升级目标

| 目标类别 | 具体目标 |
|----------|----------|
| **代码质量** | 修复所有 P0/P1 级别代码问题，消除重复文件，明确模块职责 |

## 四、风险与依赖

### 4.1 技术风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| AI 组件依赖后端 API | 中 | 高 | 优先使用 Mock 数据开发，后端 API 就绪后切换 |
| 拖拽排序实现复杂 | 中 | 中 | 使用成熟的拖拽库（@dnd-kit 或 react-beautiful-dnd） |
| i18n 文本提取遗漏 | 高 | 中 | 使用脚本扫描所有 `.tsx` 文件，人工复核 |
| 报价转合同数据结构差异 | 中 | 中 | 提前分析报价和合同的数据结构差异，设计转换逻辑 |

### 4.2 依赖风险

| 依赖 | 风险 | 缓解措施 |
|------|------|----------|
| 项目 B 代码可用性 | 项目 B 代码可能不完整或有 bug | 提前拉取项目 B 代码，进行功能验证 |
| 后端 API 支持 | 部分功能（如 AI 洞察、合同创建）需要后端 API 支持 | 提前与后端团队沟通 API 需求，或使用 Mock 数据先行开发 |

### 4.3 进度风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| Bug 修复工作量超预期 | 中 | 高 | 优先修复阻断性 Bug，非关键 Bug 可延后 |
| 国际化工作量低估 | 高 | 中 | 预留 20% 缓冲时间，优先提取核心页面文本 |
| Mock 数据不完整 | 中 | 中 | 优先完善核心模块 Mock，边缘功能可延后 |
